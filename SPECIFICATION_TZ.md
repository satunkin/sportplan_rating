# Техническое задание на разработку

Проект: `Кубок Циклон · 2026`

Назначение документа: описать текущую продуктовую логику проекта так, чтобы на основе этого документа можно было разработать новую версию системы без привязки к существующей технической реализации.

## 1. Краткое описание продукта

`Кубок Циклон · 2026` — это сезонная рейтинговая система для любительских спортсменов в циклических видах спорта.

Система должна:

- публиковать общий рейтинг сезона;
- показывать календарь соревнований и результаты участников рейтинга;
- принимать результаты спортсменов через Telegram-бота;
- давать администратору инструменты для проверки результатов, ведения соревнований, спортсменов, клубов и тренеров;
- рассчитывать очки по утвержденной формуле;
- сохранять прозрачную историю заявок и решений модерации.

Главный продуктовый принцип: в публичный рейтинг попадают только проверенные активные результаты.

## 2. Цели продукта

1. Дать спортсменам понятный сезонный рейтинг, который мотивирует участвовать в стартах.
2. Сделать правила начисления очков прозрачными и проверяемыми.
3. Упростить администратору регулярную работу с результатами и протоколами.
4. Снизить риск ошибок: дубликатов, неверных групп, неверных протоколов, автоматического объединения чужих профилей.
5. Сохранить простую модель участия: спортсмен работает через Telegram, публичная информация доступна на сайте.

## 3. Роли пользователей

### 3.1. Гость

Неавторизованный пользователь сайта.

Может:

- смотреть главную страницу с топом рейтинга;
- смотреть полный рейтинг;
- фильтровать рейтинг;
- смотреть соревнования;
- открывать карточки соревнований;
- смотреть правила;
- читать инструкцию по участию;
- открывать публичные карточки клубов и тренеров;
- перейти в Telegram-бота.

### 3.2. Спортсмен

Участник рейтинга.

Основной интерфейс спортсмена — Telegram-бот.

Может:

- зарегистрироваться;
- указать имя, дату рождения, пол и настройки публичности Telegram;
- отправить результат на проверку;
- предложить новое соревнование, если его нет в списке;
- предложить клуб или тренера;
- смотреть свои результаты;
- смотреть свое место и очки;
- запросить изменение подтвержденного результата;
- запросить удаление подтвержденного результата;
- обновить основные данные профиля.
- подтвердить или отклонить автоматически найденный результат соревнований, присланный в бот с сервера

### 3.3. Администратор

Пользователь, отвечающий за достоверность данных.

Может:

- входить в административный кабинет;
- создавать и редактировать соревнования;
- управлять дистанциями соревнований;
- загружать или импортировать протоколы;
- редактировать benchmark пятого места по группам;
- создавать и редактировать зачетные группы внутри соревнования
- создавать и редактировать спортсменов;
- архивировать, удалять и восстанавливать спортсменов;
- добавлять и редактировать результаты спортсменов вручную;
- проверять заявки спортсменов;
- подтверждать или отклонять заявки;
- модерировать предложения соревнований, клубов, тренеров;
- модерировать безопасное связывание Telegram-профиля с уже существующим спортсменом;
- объединять дублирующиеся профили спортсменов;
- управлять справочниками клубов и тренеров;
- видеть черновой раздел рассылок.

## 4. Основные разделы сайта

### 4.1. Главная страница

Назначение: быстро показать суть рейтинга и текущих лидеров.

Содержит:

- сезон `2026`;
- короткое объяснение: мужской и женский зачеты считаются отдельно;
- правило: в итог сезона идут три лучших подтвержденных результата;
- ссылки на полный рейтинг и правила;
- три текстовых блока:
  - указание, что результат сравнивается с пятым местом в группе;
  - указание, что есть два независимых зачета по полу;
  - указание, что в зачет идут три лучших старта;
- две колонки рейтинга:
  - мужчины, топ-10;
  - женщины, топ-10.

Поведение рейтинговых строк:

- внутри строки — позиция в протоколе, имя + фамилия, общее количество баллов, мелко три лучших результата (соревнования, дистанция, время);
- строки компактные по высоте, примерно как записи в протоколах соревнований
- строку спортсмена можно раскрыть;
- в раскрытии показываются все результаты спортсмена;
- три лучших по баллам результата показываются `в зачете`, остальные группой без пометок;
- клубы, тренеры и публичный Telegram username показываются только если они есть и разрешены настройками публичности спортсмена.

### 4.2. Полный рейтинг

Назначение: дать полный список участников рейтинга сезона.

Содержит:

- мужской и женский рейтинги;
- поиск по имени спортсмена;
- фильтр по возрастной группе;
- фильтр по клубу;
- фильтр по тренеру;
- сброс фильтров;
- постраничный вывод по 50 строк на мужской и женский список отдельно.

Правила отображения:

- рейтинг уже рассчитан заранее;
- фильтры только сокращают отображаемый список;
- фильтры не меняют формулу и не пересчитывают места;
- на мобильном экране мужской и женский зачеты переключаются вкладками;
- на широком экране мужской и женский зачеты показываются двумя колонками.

Строка рейтинга показывает:

- место;
- имя спортсмена;
- возрастную группу;
- количество подтвержденных стартов;
- итоговые очки;
- раскрытие с деталями результатов.
- строки компактные по высоте, примерно как записи в протоколах соревнований

### 4.3. Соревнования

Назначение: показать календарь сезона и прошедшие старты.

Содержит:

- фильтр по дисциплине;
- блок будущих стартов;
- блок прошедших стартов.

Строка соревнования показывает:

- дату;
- город;
- серию, если указана;
- название;
- список дистанций;
- для будущего старта — ссылку на регистрацию или страницу соревнования;
- для прошедшего старта — количество участников рейтинга и количество строк протокола.
- при нажатии на строку соревнования раскрывается полная карточка соревнования

### 4.4. Карточка соревнования

Назначение: показать подробности конкретного соревнования.

Содержит:

- статус: будущий старт или прошедшее соревнование;
- название;
- дату;
- город;
- серию;
- внешнюю ссылку:
  - для будущего старта — регистрация;
  - для прошедшего — официальный протокол или результаты;
- список дистанций.

Для каждой дистанции показывается:

- дисциплина;
- название дистанции;
- группы протокола и benchmark пятого места, если данные есть;
- таблица подтвержденных участников рейтинга для прошедших стартов.

Таблица участников дистанции показывает:

- спортсмена;
- возрастную группу;
- финишное время;
- место в группе или абсолюте;
- начисленные очки.

Если старт будущий, вместо таблицы показывается сообщение, что результаты появятся после старта.

### 4.5. Правила

Назначение: объяснить расчет рейтинга понятным языком.

Содержит:

- что в рейтинг попадают только подтвержденные результаты активного сезона;
- что `DNS`, `DNF`, `DSQ` не учитываются;
- формулу начисления очков;
- таблицу категорий и базовых очков;
- случаи ручной проверки;
- правила разрешения равенства очков.

### 4.6. Как участвовать

Назначение: объяснить путь спортсмена.

Содержит:

- указание, что спортсмен работает через Telegram-бота;
- шаги:
  1. зарегистрироваться в боте;
  2. отправлять результаты после стартов;
  3. дождаться проверки;
  4. следить за рейтингом на сайте;
- перечень данных, которые нужны для результата:
  - название соревнования;
  - дата;
  - дисциплина;
  - дистанция;
  - финишное время;
  - ссылка на официальный протокол;
  - место в возрастной группе, если есть;
- ссылка на Telegram-бота, если она настроена.

### 4.7. Публичная карточка клуба

Назначение: показать участников рейтинга, связанных с клубом.

Содержит:

- название клуба;
- ссылку на сайт клуба, если есть;
- список активных спортсменов клуба, участвующих в рейтинге 2026;
- место и очки каждого спортсмена;
- ссылку на полный рейтинг с фильтром по клубу.

### 4.8. Публичная карточка тренера

Назначение: показать спортсменов рейтинга, связанных с тренером.

Содержит:

- имя тренера;
- список активных спортсменов тренера в рейтинге 2026;
- место и очки каждого спортсмена;
- ссылку на полный рейтинг с фильтром по тренеру.

## 5. Административный кабинет

Административный кабинет расположен в разделе `/cabinet`.

Если пользователь не вошел как администратор, он должен попасть на страницу входа.

### 5.1. Главная панель администратора

Назначение: дать обзор состояния рейтинга и быстрые входы в рабочие разделы.

Содержит:

- счетчик заявок на проверке;
- счетчик активных соревнований;
- счетчик активных спортсменов;
- счетчик администраторов;
- форму быстрого создания соревнования;
- форму создания спортсмена;
- форму создания администратора;
- списки ближайших будущих и прошедших стартов;
- последние заявки на проверке;
- список спортсменов;
- ссылки на профильные разделы.

### 5.2. Управление соревнованиями

Администратор может:

- создать соревнование;
- указать название;
- дату;
- город;
- серию;
- ссылку на страницу соревнования;
- ссылку на регистрацию;
- ссылку на результаты;
- добавить одну или несколько дистанций;
- для каждой дистанции указать дисциплину, название дистанции и ссылку на протокол;
- загрузить файл протокола на уровне соревнования или отдельной дистанции;
- открыть публичную карточку соревнования;
- отправить соревнование в архив;
- восстановить соревнование из архива.

Правило архивации:

- архивация соревнования архивирует все его дистанции;
- восстановление соревнования восстанавливает все его дистанции.

### 5.3. Управление дистанциями

Дистанция является частью соревнования.

Для дистанции хранятся:

- дисциплина;
- название дистанции;
- ссылка на источник протокола;
- категория рейтинга, если выбрана;
- строки импортированного протокола;
- группы протокола;
- benchmark пятого места для каждой группы.

Администратор может:

- добавить дистанцию к соревнованию;
- загрузить протокол для дистанции;
- импортировать протокол по ссылке, если источник поддерживается;
- вручную изменить benchmark пятого места для группы;
- оставить примечание к ручному benchmark.

### 5.4. Управление спортсменами

Администратор может:

- видеть список активных спортсменов;
- искать спортсменов по имени, городу, телеграм-имени и возрастной группе;
- открыть архив спортсменов;
- убрать спортсмена в архив;
- удалить спортсмена совсем;
- восстановить спортсмена из архива;
- создать спортсмена вручную;
- открыть карточку спортсмена.

Карточка спортсмена содержит:

- имя;
- фамилию;
- год рождения;
- пол;
- город;
- возрастную группу (создается автоматически, если указан год рождения);
- настройку публичности результатов;
- Telegram username;
- настройку показа Telegram в рейтинге;
- связанные клубы;
- связанных тренеров;
- место и очки в рейтинге;
- историю заявок и результатов.

Администратор может в карточке спортсмена:

- редактировать профиль;
- архивировать или восстановить спортсмена;
- добавить новый результат;
- отредактировать существующую заявку;
- удалить или архивировать результат.

### 5.5. Очередь проверки результатов

Назначение: обработка заявок спортсменов.

В очередь попадают заявки со статусом `на ручной проверке`.

В списке заявок администратор видит:

- спортсмена;
- соревнование;
- дисциплину;
- дистанцию;
- дату;
- финишное время;
- заявленную возрастную группу;
- предложенный или найденный benchmark пятого места;
- подсказку по категории;
- признаки риска:
  - нет публичного протокола;
  - возрастная группа не совпадает с профилем;
  - есть похожие заявки на тот же старт;
- ссылку на протокол, если она есть.

Быстрое подтверждение доступно только если:

- определена категория рейтинга;
- найдено или введено время пятого места;
- заявка не требует обязательного комментария модератора.

Расширенная карточка заявки позволяет:

- выбрать категорию рейтинга;
- указать время пятого места;
- указать место в абсолюте;
- указать место в возрастной группе;
- добавить локацию события;
- оставить комментарий;
- отметить спорные условия:
  - нет публичного протокола;
  - объединены возрастные группы;
  - в группе меньше пяти финишеров.

Если заявка подтверждается при спорных условиях, комментарий модератора обязателен.

### 5.6. Модерация предложений

Администратор видит предложения из Telegram:

- новое соревнование;
- новый клуб;
- новый тренер.

Администратор может:

- одобрить предложение и создать новую сущность;
- объединить предложение с уже существующей сущностью;
- отклонить предложение;
- оставить комментарий.

Если спортсмен предложил клуб или тренера и предложение одобрено, связь между спортсменом и клубом/тренером должна быть создана автоматически.

### 5.7. Безопасное связывание Telegram с существующим спортсменом

Если спортсмен регистрируется в Telegram и система находит похожий уже существующий профиль, автоматического объединения быть не должно.

Должен создаваться запрос на связывание.

Администратор должен вручную:

- увидеть кандидата;
- проверить данные;
- одобрить связывание;
- отклонить связывание.

После одобрения Telegram ID связывается с существующим пользователем/спортсменом.
Если администратор отклоняет связывание профилей, то в системе остаются оба спортсмена, существующий и новый из Телеграма.

### 5.8. Справочники клубов и тренеров

Администратор может:

- создать клуб;
- создать тренера;
- указать сайт клуба или тренера, если есть;
- отправить клуб или тренера в архив или удалить;
- восстановить из архива;
- видеть количество связанных спортсменов.

Клубы и тренеры являются публичными фильтрами рейтинга и ссылками из раскрытия строки спортсмена.

### 5.9. Рассылки

Текущий раздел рассылок является заготовкой интерфейса.

Он должен показывать:

- выбор аудитории;
- фильтр по полу;
- фильтр по возрастной группе;
- фильтр по участию в старте;
- фильтры по наличию подтвержденных результатов;
- текст сообщения;
- preview сообщения;
- оценку количества получателей.

Фактическая массовая отправка Telegram-сообщений пока не считается реализованной частью продукта.

## 6. Telegram-бот

Telegram-бот — основной интерфейс спортсмена.

### 6.1. Главное меню

Меню содержит действия:

- `Добавить результат`;
- `Мои результаты`;
- `Моё место в рейтинге`;
- `Мои данные`;
- `Помощь`.

Команда `/cancel` отменяет текущий ввод.

### 6.2. Регистрация спортсмена

Сценарий:

1. Спортсмен запускает `/start`.
2. Если Telegram ID уже связан со спортсменом, бот показывает главное меню.
3. Если связи нет, бот запускает регистрацию.
4. Бот запрашивает полное имя минимум из двух слов.
5. Бот запрашивает год рождения в формате `ГГГГ`.
6. Бот запрашивает пол: мужской или женский.
7. Бот спрашивает, можно ли показывать Telegram username в раскрытии рейтинга.
8. Система пытается найти существующего активного спортсмена с такой же датой рождения и похожим именем.
9. Если кандидат найден, создается запрос на ручное связывание, с указанием Имени, Фамилии, года рождения и имеющихся результатов.
10. Если кандидат не найден, создается новый спортсмен.

Требования:

- нельзя автоматически объединять Telegram-профиль с существующим спортсменом;
- имя должно содержать минимум два слова;
- год рождения должен быть валидным (от 1930 до 2010);
- возрастная группа рассчитывается автоматически на текущий год.

### 6.3. Добавление результата

Сценарий:

1. Спортсмен выбирает `Добавить результат`.
2. Бот показывает список активных соревнований.
3. Если нужного соревнования нет, спортсмен может предложить новое.
4. Спортсмен выбирает соревнование.
5. Спортсмен выбирает дистанцию.
6. Бот просит ввести финишное время.
7. Бот просит ввести время пятого места в своей группе с указанием группы или отправить `-`.
8. Бот показывает summary заявки.
9. Спортсмен подтверждает отправку.
10. Заявка попадает в очередь администратора.

Требования:

- финишное время должно быть в формате `ММ:СС` или `ЧЧ:ММ:СС`;
- время пятого места может отсутствовать;
- дубликат такой же заявки не должен создаваться;
- заявка не попадает в рейтинг до подтверждения администратором.

### 6.4. Предложение нового соревнования

Если соревнования нет в списке, спортсмен может предложить новое.

Бот запрашивает:

- название соревнования;
- дату;
- локацию / город
- дистанцию;
- дисциплину.

После отправки создается предложение для администратора.

### 6.5. Мои результаты

Бот показывает:

- подтвержденные результаты с отметкой входит в топ-3 или нет;
- очки за каждый подтвержденный результат;
- заявки на проверке;
- отклоненные заявки;
- кнопки изменения или удаления подтвержденных результатов.

### 6.6. Изменение результата

Если спортсмен хочет изменить подтвержденный результат:

1. Он выбирает результат.
2. Вводит новые данные.
3. Система создает заявку типа `изменение`.
4. Старый подтвержденный результат продолжает действовать.
5. После одобрения администратором старый результат архивируется, новый становится активным.

### 6.7. Удаление результата

Если спортсмен хочет удалить подтвержденный результат:

1. Он выбирает удаление.
2. Система создает заявку типа `удаление`.
3. Старый результат продолжает действовать до решения администратора.
4. После одобрения результат архивируется и рейтинг пересчитывается.

### 6.8. Мое место в рейтинге

Бот показывает:

- имя спортсмена;
- текущее место;
- итоговые очки;
- три лучших результата;
- ссылку на полный рейтинг.

### 6.9. Мои данные

Бот показывает:

- имя;
- дату рождения;
- возрастную группу;
- клубы;
- тренеров;
- статус публичности Telegram.

Спортсмен может:

- изменить имя;
- изменить дату рождения;
- предложить клуб;
- предложить тренера;
- включить или выключить показ Telegram username.

## 8. Алгоритмы и правила

### 8.1. Расчет возрастной группы

Возраст спортсмена для сезона считается на конец года активного сезона.

Для сезона 2026 возраст считается на `31.12.2026`.

Правила группы:

- мужчины получают префикс `M`;
- женщины получают префикс `F`;
- младше 18 лет: `U18`;
- 18-24: `18-24`;
- далее группы идут пятилетками:
  - `25-29`;
  - `30-34`;
  - `35-39`;
  - и так далее.

Примеры:

- мужчина 36 лет: `M35-39`;
- женщина 29 лет: `F25-29`.

### 8.2. Разбор времени

Система должна принимать время:

- `ММ:СС`;
- `ЧЧ:ММ:СС`.

Внутри расчетов время переводится в секунды.

Некорректное время не должно сохраняться как расчетное.

### 8.3. Расчет отставания

Для результата берется:

- финишное время спортсмена;
- время пятого места в его возрастной группе.

Формула:

```text
lagPercent = ((athleteFinishSeconds - fifthPlaceSeconds) / fifthPlaceSeconds) * 100
```

Если спортсмен быстрее пятого места, отставание считается равным `0`.

Значение округляется до двух знаков после запятой.

### 8.4. Расчет очков

Формула:

```text
points = round(basePoints * exp(-0.077 * lagPercent))
```

Где:
- `basePoints` — базовые очки категории;
- `lagPercent` — процент отставания от пятого места.

Для спортсменов, занявших места 1-4 в группе, добавляются бонусные очки, считаемые от бонуса за 1 место.
Бонусные очки за первое место по категориям:
|Спринт / 5 км бег / аналоги | 600 |
| Олимпийка / 10 км бег / аналоги | 720 |
| HalfIronman / 21,1 км бег / аналоги | 960 |
| Ironman / 42,2 км бег / аналоги | 1200 |

Бонусы за второе, третье и четвертое места рассчитываются автоматически с использованием коэффициента конкуренции возрастной группы.

Коэффициент конкуренции возрастной группы: 
Коэффициент конкуренции возрастной группы (ККВГ) характеризует плотность спортивной борьбы внутри конкретной возрастной группы.
Коэффициент определяется по результатам первого и пятого мест.
Формула расчета:
ККВГ=1−((T₅−T₁) / T₁)
где:
* T₁ — результат победителя возрастной группы;
* T₅ — результат спортсмена, занявшего пятое место.
Полученное значение округляется до трех знаков после запятой

Бонусы начисляются следующим образом:
* 1 место = базовый бонус;
* 2 место = бонус 1 места × ККВГ;
* 3 место = бонус 2 места × ККВГ;

Малочисленные возрастные группы

Возрастные группы подразделяются на три категории.

Одиннадцать и более финишировавших спортсменов
Рейтинговые и бонусные очки начисляются по общим правилам.
Коэффициент конкуренции возрастной группы используется только при расчете бонусных
очков.

От пяти до десяти финишировавших спортсменов
Рейтинговые очки рассчитываются по общим правилам.
После расчета все начисленные спортсмену очки умножаются на коэффициент
конкуренции возрастной группы.
Корректировке подлежат:
* рейтинговые очки;
* бонусные очки.

Менее пяти финишировавших спортсменов
Возрастная группа считается несостоявшейся для целей рейтинга.
Рейтинговые и бонусные очки не начисляются


Правила:

- максимум за результат равен базовым очкам категории + бонусным очкам;
- минимум равен `0`;
- чем больше отставание, тем меньше очков.
- результат округляется до целых значений

### 8.5. Benchmark пятого места

Приоритет источников:

1. Импортированный протокол.
2. Ручное значение администратора.
3. Подсказка спортсмена, ожидающая проверки.

Если в группе меньше пяти финишеров, такой результат автоматически не идет в зачет рейтинга.

### 8.6. Импорт протокола

Система должна уметь принимать протокол:

- по ссылке из поддерживаемого источника;
- через файл `XLS`, `XLSX` или `CSV`;
- PDF может быть показан в интерфейсе, но без полноценного парсера должен возвращать понятную ошибку.

После импорта:

1. Старые строки протокола для дистанции заменяются новыми.
2. Каждая строка нормализуется.
3. Финишное время переводится в секунды, если возможно.
4. Пол пытается определиться из пола или возрастной группы.
5. Строки группируются по возрастной группе, полу или открытой группе.
6. Для каждой группы сортируются финишные времена.
7. Пятое время становится benchmark группы.
8. Если пятого времени нет, benchmark остается пустым.
9. Если в протоколе больше разных групп, чем стандартно (стандартно — деление по полу + диапазон в 5 лет), результаты группируются по стандартным группам
10. Система сверяет список зарегистрированных спортсменов с протоколом и при нахождении спортсмена в протоколе формирует заявку администратору на добавление нового результата

Если файл содержит несколько дистанций, система должна уметь распределять строки по дистанциям. Если дистанций несколько, а в файле нет колонки дистанции, администратор должен получить ошибку.

### 8.7. Проверка заявки

При подтверждении заявки администратор должен указать или подтвердить:

- категорию рейтинга;
- время пятого места;
- при необходимости комментарий.

Система должна:

1. проверить дубликаты;
2. найти или создать соответствующую дистанцию;
3. рассчитать отставание;
4. рассчитать очки;
5. создать или обновить подтвержденный результат;
6. обновить статус заявки;
7. записать решение модерации;
8. пересчитать рейтинг сезона;
9. отправить Telegram-уведомление спортсмену, если он связан с ботом.

### 8.8. Дубликаты

Система не должна создавать дубликаты для одного спортсмена с одинаковыми:

- сезоном;
- соревнованием;
- датой;
- дисциплиной;
- дистанцией;
- финишным временем.

При подтверждении новой заявки система дополнительно проверяет, нет ли уже подтвержденного дубля.

### 8.9. Изменение подтвержденного результата

Подтвержденный результат нельзя менять напрямую от имени спортсмена.

Правильный поток:

1. Создается заявка типа `изменение`.
2. Старый результат остается активным.
3. Администратор проверяет заявку.
4. После подтверждения старый результат архивируется.
5. Новый результат становится активным.
6. Рейтинг пересчитывается.

### 8.10. Удаление подтвержденного результата

Подтвержденный результат нельзя удалять сразу по запросу спортсмена.

Правильный поток:

1. Создается заявка типа `удаление`.
2. Старый результат остается активным.
3. Администратор проверяет заявку.
4. После подтверждения результат архивируется.
5. Рейтинг пересчитывается.

### 8.11. Расчет рейтинга

Рейтинг считается отдельно для мужчин и женщин.

В расчет входят:

- только активные подтвержденные результаты;
- только активные спортсмены;
- только результаты активного сезона.

Для каждого спортсмена:

1. Берутся все активные подтвержденные результаты сезона.
2. Результаты сортируются по очкам от большего к меньшему.
3. В итоговые очки входят только три лучших результата.
4. Количество подтвержденных результатов сохраняется отдельно.

Сортировка рейтинга:

1. Больше итоговых очков.
2. Больше итоговых очков за все подтвержденные результаты
3. Больше очков за лучший результат.
4. Больше очков за второй результат.
5. Больше очков за третий результат.
6. Больше подтвержденных результатов.
7. Если все показатели равны, спортсмены делят место.

Если показатели полностью совпадают, место должно быть одинаковым.

### 8.12. Архивация

В продукте действует политика `archive-first`.

Это значит:

- соревнования не удаляются физически, а архивируются;
- дистанции архивируются вместе с соревнованием;
- спортсмены архивируются;
- подтвержденные результаты архивируются;
- архивные сущности не должны попадать в активные публичные выборки.

Физическое удаление допустимо только для неподтвержденных черновых/ошибочных данных, где это явно безопасно.

### 8.13. Публичность Telegram

Telegram username спортсмена показывается в раскрытии рейтинга только если:

- username сохранен;
- спортсмен разрешил публичный показ.

## 9. Статусы

### 9.1. Статусы активных сущностей

- `pending` — ожидает проверки;
- `active` — активна;
- `archived` — в архиве.

### 9.2. Статусы заявки результата

- `pending_auto_check` — ожидает автоматической проверки;
- `pending_manual_review` — ожидает ручной проверки;
- `verified` — подтверждена;
- `rejected` — отклонена.

### 9.3. Типы заявки результата

- `create` — новый результат;
- `update` — изменение подтвержденного результата;
- `delete` — удаление подтвержденного результата.

### 9.4. Решения модерации

- `approved` — одобрено;
- `rejected` — отклонено;
- `needs_info` — нужна дополнительная информация.

### 9.5. Статусы предложений

- `pending` — ожидает проверки;
- `approved` — одобрено;
- `rejected` — отклонено;
- `merged` — объединено с существующей сущностью.

## 10. Нотификации

После решения по заявке спортсмен должен получить уведомление в Telegram, если его профиль связан с Telegram.

Тексты по смыслу:

- результат подтвержден и добавлен в рейтинг;
- изменение результата подтверждено, рейтинг пересчитан;
- удаление результата подтверждено, рейтинг пересчитан;
- заявка отклонена администратором.

Попытки отправки должны логироваться.

Если отправка не удалась, ошибка должна сохраняться. Автоматические ретраи могут быть отдельным этапом.
